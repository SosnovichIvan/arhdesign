## ADDED Requirements

### Requirement: Автоматическая Hero-карусель

Hero Desktop Light и Desktop Dark MUST отображать одну и ту же циклическую карусель реальных проектных фотографий.

#### Scenario: Автопереключение кадра

- **WHEN** пользователь просматривает Hero в prototype
- **THEN** текущая фотография меняется через 3 секунды с dissolve 300 ms.

### Requirement: Адаптивные Hero-карусели

Tablet и Mobile в обеих темах MUST использовать ту же 30-кадровую последовательность в component set с нативными размерами Hero-media.

#### Scenario: Проверка адаптивных вариантов

- **WHEN** пользователь открывает Tablet или Mobile Light/Dark
- **THEN** изображение занимает существующую media-область без растяжения, обрезания или изменений Hero-copy.

### Requirement: Переиспользуемые component set

Hero-карусель MUST быть оформлена отдельными component set для Desktop, Tablet и Mobile. Все Hero-макеты MUST содержать только INSTANCE соответствующего viewport‑компонента.

#### Scenario: Проверка структуры Figma

- **WHEN** дизайнер открывает любой Hero Concept A
- **THEN** media-карусель является INSTANCE с property `Frame`, а её variants, previews, controls и prototype‑переходы определены в component set, а не локально в экране.

### Requirement: Полная последовательность проектов

Карусель MUST проходить 30 кадров в порядке «Современная гармония» 01–10, «Атмосфера уюта» 01–10, «Современный минимализм» 01–10 и возвращаться к первому кадру.

#### Scenario: Переход между проектами

- **WHEN** завершается десятый кадр одного проекта
- **THEN** следующим показывается первый кадр следующего проекта без смешения наборов.

### Requirement: Сохранение Hero-композиции

Карусель MUST сохранять габариты и кадрирование текущего Hero-media; controls располагаются внутри media‑области и не изменяют Hero-copy или сетку.

#### Scenario: Визуальная проверка

- **WHEN** сравниваются исходный Hero и первый кадр карусели
- **THEN** изображение занимает ту же media-область без изменений текста, сетки или темы.

### Requirement: Preview и ручная навигация

Hero-карусель MUST содержать preview‑миниатюры, счётчик `текущий / 30` и кнопки `←`/`→` по паттерну project case-study.

#### Scenario: Ручная смена кадра

- **WHEN** пользователь нажимает `←` или `→`
- **THEN** карусель переходит к предыдущему или следующему кадру в цикле и продолжает автоматическое переключение.

#### Scenario: Визуальная идентификация

- **WHEN** пользователь видит Hero-media
- **THEN** он различает, что это карусель, по миниатюрам и счётчику, а текущий preview отмечен accent‑обводкой.

### Requirement: Единые карусели страниц «Проект»

Каждая страница «Проект» MUST использовать INSTANCE общего `Project Carousel` для своего viewport, а не локальный media-frame. Компонент MUST сохранять галерею из десяти кадров только своего проекта и использовать тот же reusable `Carousel Controls`, что и Hero-карусель.

#### Scenario: Адаптивная галерея проекта

- **WHEN** пользователь открывает любой проект в Desktop, Tablet или Mobile, Light или Dark
- **THEN** он видит 10 кадров только выбранного проекта, счётчик `текущий / 10`, активную preview-миниатюру и controls единого визуального стиля.

#### Scenario: Циклическая смена фотографий проекта

- **WHEN** достигнут десятый кадр галереи проекта или пользователь нажимает стрелку next
- **THEN** карусель возвращается к первому кадру этого же проекта через dissolve 300 ms и не показывает кадры другого проекта.
