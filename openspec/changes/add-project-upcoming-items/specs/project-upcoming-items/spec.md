## ADDED Requirements

### Requirement: Защищённое создание ближайших записей

Система MUST создавать задачу или встречу только для authenticated
`super_admin`, active `customer` или active `project_admin` выбранного проекта и
MUST проверять право на сервере.

#### Scenario: Разрешённое создание задачи

- **WHEN** разрешённый участник отправляет название, описание и будущий дедлайн
- **THEN** задача и audit создаются атомарно, а ответ содержит сохранённую запись.

#### Scenario: Чужой проект

- **WHEN** пользователь без active membership отправляет прямой create request
- **THEN** сервер не создаёт запись и возвращает скрывающий ресурс `404`.

#### Scenario: Некорректная встреча

- **WHEN** окончание встречи не позже начала либо время невалидно
- **THEN** сервер возвращает validation error без частичной записи.

### Requirement: Ограниченный feed ближайшего периода

Система MUST возвращать задачи и встречи проекта в полуинтервале
`[now, now + days)`, где `days` находится в диапазоне 1–90, в стабильном порядке
и только пользователю с доступом к проекту.

#### Scenario: Смешанный feed

- **WHEN** в период попадают задача и встреча
- **THEN** ответ содержит обе записи с различимым `kind` и effective time.

#### Scenario: Запись за пределами периода

- **WHEN** дедлайн или начало встречи позже выбранной границы
- **THEN** запись отсутствует в feed и появляется после увеличения периода.

### Requirement: Управление блоком «Ближайшее по проекту»

Интерфейс MUST показывать кнопки создания задачи, встречи и настройки периода,
MUST поддерживать период 1–90 дней и фильтры «Все / Задачи / Встречи».

#### Scenario: Создание и немедленное отображение

- **WHEN** пользователь успешно создаёт запись в доступном периоде
- **THEN** диалог закрывается, появляется подтверждение и новая запись видна в
  блоке без перезагрузки страницы.

#### Scenario: Настройка периода

- **WHEN** пользователь изменяет период
- **THEN** подзаголовок и feed обновляются, а значение сохраняется для этого
  пользователя и проекта в БД и восстанавливается в любом его браузере.

#### Scenario: Независимые настройки участников

- **WHEN** два пользователя выбирают разные периоды в одном проекте
- **THEN** каждый видит собственный период, а изменение одного пользователя не
  меняет настройку другого.

#### Scenario: Персональная тема

- **WHEN** авторизованный пользователь меняет светлую или тёмную тему
- **THEN** тема сохраняется в БД на уровне пользователя и восстанавливается при
  входе с другого браузера независимо от выбранного проекта.

#### Scenario: Доступность действий

- **WHEN** пользователь использует клавиатуру или screen reader
- **THEN** каждая icon-only кнопка имеет однозначное доступное имя, видимый focus
  и открывает диалог с управляемым фокусом.
