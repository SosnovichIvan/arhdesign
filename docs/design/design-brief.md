# Design brief

## Задача

Показать почерк и компетентность архитектора-дизайнера за 5–10 секунд, затем дать посетителю доказательства через проекты и простой путь к первичному контакту.

## Аудитории

- владелец квартиры или дома, выбирающий специалиста;
- девелопер/бизнес, ищущий архитектурную или интерьерную экспертизу;
- партнёр, редакция или потенциальный сотрудник, проверяющий авторство и опыт.

## Структура главной

1. Header: имя/знак, проекты, услуги, об авторе, контакт, тема.
2. Hero: позиционирование, география, ключевой проект, CTA.
3. Избранные проекты: 4–6 работ с контрастным ритмом изображений.
4. Подход: короткий тезис и 3–4 этапа.
5. Услуги: конкретный результат, а не общий список компетенций.
6. Профиль: фото, биография, опыт, публикации/награды только при наличии.
7. Контакт: понятный следующий шаг и необходимые данные для старта.
8. Footer: компактный блок высотой около `176 px`; слева — короткий смысловой тезис об архитектуре и интерьерах, справа — контакты в двух колонках: телефон/почта и иконки VK/Telegram/MAX. Copyright с годом и именем автора выровнен по центру нижней строки. Отдельный бренд-блок, часовой пояс и дублирующая навигация не используются. Ссылка на политику конфиденциальности добавляется после подготовки юридически согласованной страницы.

## Responsive states

- Desktop: 1440 px, content max 1280 px, 12 columns.
- Tablet: 768 px, 8 columns.
- Mobile: 390 px, 4 columns; проверка также на 320 px.
- Контентный порядок не зависит от декоративного desktop-расположения.
- Каждый UI-компонент в Figma MUST иметь явные варианты `Viewport=Desktop`, `Viewport=Tablet` и `Viewport=Mobile` для всех применимых тем и состояний. Даже если геометрия компонента не меняется, одинаковые viewport-варианты создаются явно и документируются как инвариантные.
- Корневой контейнер каждой секции и размещённый в ней композиционный компонент MUST занимать `100%` ширины области применения. Ограничение контента выполняется внутренними responsive gutters/padding, а не уменьшением ширины самого компонента; рекомендуемый Tailwind-паттерн: `w-full px-4 md:px-6 xl:px-20`.
- Для каждого viewport-варианта MUST быть определены размеры, touch target, перенос текста, поведение вложенных элементов и соответствующие Tailwind breakpoint-классы.
- Раскрытое меню на Tablet и Mobile MUST отображаться поверх следующего блока, не участвовать в потоке страницы и не вызывать layout shift. Панель начинается сразу под header, использует семантический фон с opacity около 94–95% и мягкую тень; рекомендуемый Tailwind-паттерн: `absolute inset-x-0 top-full bg-page/95 shadow-xl`.
- Активный пункт навигации MUST определяться текущим маршрутом через `aria-current="page"`. На Desktop он выделяется акцентным underline и поверхностью; на Tablet/Mobile — левым акцентным маркером и поверхностью. Активность не моделируется отдельным вариантом для каждого URL; рекомендуемый Tailwind-паттерн: `[aria-current=page]:bg-surface [aria-current=page]:text-accent`.

## Темы и токены

- Светлая: `bg #F4F1EA`, `surface #FBFAF7`, `text #1E211F`, `muted #6C706C`, `border #D7D3CA`, `accent #6F7868`.
- Тёмная: `bg #111310`, `surface #191C18`, `text #F0EEE8`, `muted #A9ACA5`, `border #343831`, `accent #B7C2AE`.
- Цвета предварительные и будут созданы как semantic variables с Light/Dark modes после утверждения.
- Предпочтительная типографика: Manrope для UI/текста; Cormorant Garamond для editorial display в концепции A. Все указанные семейства доступны в Figma.

## Компоненты v1

Header, mobile menu, theme toggle, text link/button, project card, media figure, project facts, service item, process step, contact CTA и footer. Базовый Button из Simple Design System можно импортировать; уникальные project/media элементы потребуют локальных компонентов на собственных токенах.

Все UI-компоненты в production-коде MUST быть реализованы через Tailwind CSS с использованием общих семантических theme tokens. Произвольные CSS-стили и inline styles допускаются только для возможностей, которые невозможно корректно выразить Tailwind-утилитами, и должны быть явно обоснованы.

Компонент считается готовым только после проверки полной матрицы `Desktop / Tablet / Mobile × Light / Dark × применимые состояния`. Если матрица превышает 30 комбинаций, компонент MUST быть разделён на несколько связанных component sets без потери viewport-покрытия.

## Motion

150–240 ms для hover/focus/theme state; мягкое появление секции допустимо только без задержки контента; без smooth-scroll hijacking, автокаруселей и обязательного видео. `prefers-reduced-motion` отключает декоративные движения.

## Acceptance

- три desktop-концепции в Figma;
- для рекомендуемой концепции: desktop/tablet/mobile и light/dark;
- компоненты и variables связаны, повторяющиеся элементы — instances;
- каждый компонент содержит и визуально проверен в вариантах Desktop/Tablet/Mobile;
- нет обрезанного текста и пустых image placeholders;
- контраст и focus states соответствуют WCAG 2.2 AA.
