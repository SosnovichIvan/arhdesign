# ADR: контекстные обсуждения сущностей проекта

- Статус: accepted
- Дата: 2026-09-26
- Связано: `future-client-cabinet-spec.md`, раздел 5.3

## Контекст

В одном проекте может быть несколько именованных обсуждений: общий чат и чаты,
связанные с задачами, материалами и расходами. Пользователь открывает обсуждение
из списка проекта или из связанной сущности, задаёт имя при создании и выбирает
участников. Участие в чате не должно предоставлять доступ к проекту или
связанной сущности, а участие в проекте не должно автоматически давать доступ
к каждому новому чату.

## Решение

Используется существующая таблица `chats`: `kind = project` для свободного
именованного чата проекта и `kind = context` для чата сущности. Один проект
может иметь несколько активных чатов. Состав каждого чата хранится отдельно в
`chat_memberships`; читать историю и отправлять сообщения могут только активные
участники чата, супер-администратор и технический администратор. Создатель чата,
администратор заказа и глобальный администратор могут менять имя и состав.
Создателя нельзя исключить из его чата.

Команда `PUT .../chats/context` по-прежнему атомарно создаёт или возвращает чат
для конкретной сущности. Команда `POST .../chats` создаёт именованный чат
проекта с выбранными участниками. Изменение имени использует `version` для
защиты от потерянного обновления.

Контекст ограничен типами `task`, `material`, `expense`. Перед созданием,
чтением истории и отправкой каждого сообщения backend заново проверяет доступ
к проекту и исходной сущности. Для задачи учитывается назначение исполнителя и
право видеть все задачи, для материала — материальные привилегии, для расхода —
действующий доступ к финансам проекта. Недоступный ресурс возвращается как
`not found`, чтобы не раскрывать его существование.

Сообщения остаются в общей таблице `chat_messages`; идемпотентность определяется
парой `(chat_id, client_message_id)`. Транзакция создания чата одновременно
создаёт memberships и фиксирует audit event. Полиморфная ссылка на сущность
проверяется application service/repository внутри транзакции: отдельные nullable
FK не добавляются, поскольку они усложнили бы расширение списка разрешённых
контекстов. Уведомления о сообщении получают только активные участники чата.

Проектная документация хранится в `project_documents`: метаданные и содержимое
`BYTEA` фиксируются одной транзакцией. Максимальный размер файла — 10 МБ.
Активный участник проекта может загрузить и открыть документ; удалить его может
загрузивший пользователь, администратор заказа, супер-администратор или
технический администратор. Удаление логическое, поэтому содержимое остаётся
доступным для восстановления до отдельной процедуры очистки. HTTP-контракт не
раскрывает пути файловой системы.

## Рассмотренные варианты

- Отдельная таблица сообщений для каждого типа сущности отклонена из-за
  дублирования пагинации, аудита и правил идемпотентности.
- Один общий чат с `context_id` только у сообщения отклонён: он не даёт
  независимой истории и не позволяет отозвать доступ к конкретной задаче.
- Таблица `chat_context_links` остаётся вариантом пересмотра, когда одному чату
  понадобится несколько связанных сущностей.
- Объектное хранилище для файлов пока не вводится: для текущей нагрузки
  транзакционная запись в PostgreSQL проще в эксплуатации. Решение следует
  пересмотреть при росте объёма документов или необходимости потоковой загрузки.

## Последствия и проверка

Преимущество — единый transport и UI-компонент истории, явный список чатов слева
и независимое управление участниками. Цена — обязательная повторная авторизация
на каждом запросе, application-level проверка полиморфной ссылки и рост размера
PostgreSQL из-за файлов. Решение пересматривается при появлении multi-context
чатов, удаления исходных финансовых записей или росте файлового архива.

Проверка: PostgreSQL integration test подтверждает применение миграций,
membership-ограничения и целостность документов. Unit-тесты проверяют валидацию
имени, состава участников, типов и размеров файлов. Cypress проверяет создание
именованного чата в master-detail интерфейсе и загрузку, открытие и удаление
проектного документа.
