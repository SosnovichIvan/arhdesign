# R5: запросы общего календаря

Дата локального измерения: 2026-09-28. PostgreSQL 17, одна активная проектная
дорожка и одно событие; результаты подтверждают форму access path, но не заменяют
нагрузочную проверку на production-подобном объёме.

## Контракт

- период полуоткрытый `[from, to)`, не более 370 дней;
- не более 50 явно выбранных проектов;
- ответ ограничен 100 доступными проектами и 1000 событиями;
- проекты ограничиваются `super_admin` либо активным membership;
- задачи дополнительно ограничиваются `customer/project_admin`,
  `tasks.view_all` либо назначением исполнителю;
- встречи возвращаются только после отбора доступных проектов.

## План

Выборка событий использовала `project_tasks_upcoming_idx` и
`project_meetings_upcoming_idx` как index-only scan по
`(project_id, due_at|starts_at)`; execution `0.107 ms`, buffers hit `7`.
Сортировка одного результата заняла `25 kB`.

Выборка проектных дорожек на одной строке закономерно выбрала sequential scan;
execution `0.318 ms`, buffers hit `13`. Новый индекс для этого измерения не
добавлялся: цена отдельного индекса не обоснована на текущем объёме, а результат
жёстко ограничен `LIMIT 101`. Перед R5 release plan повторяется минимум на
10 000 проектах с реалистичным распределением memberships и статусов.

N+1 отсутствует: одна выборка получает проектные дорожки, вторая — все события
этих дорожек. Группировка событий по проекту выполняется в памяти в пределах
контрактных лимитов.
