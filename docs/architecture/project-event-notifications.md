# Уведомления о событиях проекта

Статус: принято для текущего этапа реализации.

## Назначение и границы

Единый модуль уведомлений аккаунта сообщает пользователю о событиях во всех
доступных ему проектах независимо от открытой страницы. Основной канал — центр
уведомлений в интерфейсе; Telegram является дополнительным каналом для
пользователей с активной привязкой. Уведомление не является источником данных и
не расширяет права: после перехода backend повторно проверяет актуальный доступ
к проекту и связанной сущности.

В текущий этап входят сообщения и жизненный цикл чатов, назначение и изменение
задач, встречи, расходы, материалы, состав участников и загрузка/удаление
проектной документации. Новые типы событий должны подключаться к этому модулю,
а не создавать отдельный центр или локальный счётчик конкретной страницы.

## Матрица событий

| Событие | Получатели | Не получает | Тип сообщения |
| --- | --- | --- | --- |
| Новое сообщение общего чата | Все активные участники проекта | Автор сообщения | `project.chat.message_created` |
| Новое сообщение контекстного чата | Активные участники, имеющие доступ к задаче, материалу или расходу | Автор и участники без доступа к записи | `project.context_chat.message_created` |
| Новая задача | Назначенные исполнители | Автор задачи, если он же исполнитель | `project.task.assigned` |
| Новая встреча | Все активные участники проекта | Автор встречи | `project.meeting.created` |
| Новый расход | Заказчик, администраторы проекта и участники с `financials.view` | Автор расхода и участники без доступа к финансам | `project.expense.created` |
| Новый материал | Участники с ролью заказчика/администратора либо `materials.view` | Автор и участники без доступа к материалам | `project.material.created` |
| Материал изменён | Участники с ролью заказчика/администратора либо `materials.view` | Автор и участники без доступа к материалам | `project.material.updated` |
| Материал удалён | Участники с ролью заказчика/администратора либо `materials.view` на момент удаления | Автор и участники без доступа к материалам | `project.material.deleted` |
| Участник добавлен | Добавленный участник и действующие администраторы проекта | Автор действия | `project.member.added` |
| Участник удалён | Действующие администраторы проекта | Автор действия; удалённый пользователь не получает подробности проекта после отзыва доступа | `project.member.removed` |
| Статус задачи изменён | Исполнители задачи, заказчик, администраторы и участники с `tasks.view_all` | Автор изменения и участники без доступа к задаче | `project.task.status_changed` |
| Документ загружен | Все активные участники проекта | Автор действия | `project.document.uploaded` |
| Документ удалён | Все оставшиеся активные участники проекта | Автор действия | `project.document.deleted` |
| Чат создан или переименован | Активные участники чата | Автор действия | `project.chat.created`, `project.chat.renamed` |
| Участник добавлен в чат или удалён из него | Активные участники чата после изменения | Автор действия | `project.chat.member_added`, `project.chat.member_removed` |
| Чат удалён | Активные участники чата на момент удаления | Автор действия | `project.chat.deleted` |

Для записи в интерфейсе обязательны активный пользователь и доступ к событию.
Для Telegram дополнительно обязательны действующая привязка, активная подписка
бота и `telegram_events_enabled = true`.
Для события добавления участника новая активная membership уже должна быть
зафиксирована в той же транзакции. Для удаления подробности не отправляются
пользователю после отзыва membership; уведомление получают только оставшиеся
администраторы.

## Транзакция, идемпотентность и отказ

Project service формирует минимальный текст, шифрует payload существующим ключом
outbox и передаёт его в команду persistence. Репозиторий в одной PostgreSQL-
транзакции сохраняет доменное изменение, аудит, запись `account_notifications`
и отдельную `notification_outbox` запись Telegram для каждого подходящего
получателя. Ключ имеет форму
`<message-type>:<event-id>:<recipient-user-id>`; повтор запроса не создаёт дубль.

Telegram worker использует существующие bounded retries. Недоступность Telegram
после commit переводит outbox в `retry` и не откатывает сообщение, задачу или
встречу. Ошибка шифрования или постановки в outbox до commit откатывает всю
операцию, чтобы не терять обязательное уведомление молча.

## Каталог представления и маршрутизация

Тип события определяет заголовок и безопасный маршрут в интерфейсе:

| Семейство | Раздел |
| --- | --- |
| `project.task.*` | задачи проекта |
| `project.meeting.*` | календарь проекта |
| `project.material.*` | материалы |
| `project.expense.*`, `project.finance.*` | финансы |
| `project.document.*` | документы |
| `project.chat.*` | конкретный чат или список чатов |
| `project.member.*` и остальные события проекта | сводка проекта |

Frontend отображает один общий счётчик непрочитанных событий и один список.
Локальные счётчики (например, непрочитанные сообщения в списке чатов) могут
дополнять его, но не создают отдельное хранилище событий аккаунта.

## Проверка

- Cypress проверяет наблюдаемую совместную работу: один пользователь отправляет
  сообщение, создаёт задачу или изменяет документацию, другой видит событие в
  общем центре и переходит в правильный раздел.
- PostgreSQL integration test проверяет точный набор получателей, исключение
  автора, настройки, права сущности, атомарность и отсутствие дублей.
- Unit-тест Telegram worker проверяет расшифровку, адресацию привязанному chat ID,
  успешную доставку и retry. Cypress не отправляет реальные сообщения во внешний
  Telegram и не подменяет эту проверку browser mock-ом.
