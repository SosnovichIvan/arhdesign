# Журнал обратной связи

## Как вести

Фиксировать только решения, полезные для следующей работы: что заметил пользователь, где это проявилось, как исправлено и стало ли правилом. Повторяемое правило переносить в конкретный skill; разовую деталь оставлять здесь.

## Зафиксированные замечания

| Контекст | Замечание и решение | Статус |
|---|---|---|
| Concept A, Profile | Убрать «Подробнее об авторе →» во всех адаптивах/темах. | Реализовано; правило — при удалении элемента проверять всю матрицу viewport/theme. |
| Concept A, Contact CTA | CTA не прилипает к нижней рамке; форма появляется по клику на «Обсудить проект». | Реализовано для Desktop Light; правило — новый user flow должен иметь target screen и prototype reaction. |
| Concept A, темы | Тёмная тема не должна оставлять светлые поверхности, тёмный текст и неподходящие action colors. | Реализовано; правило — менять tokens, проверять все применимые темы. |
| Concept A, Profile facts | Метки «Фокус» и «География» имеют вторичный стиль, а значения — основной; отступы читаемы. | Реализовано; частная типографическая деталь. |
| Catalog | «Все проекты» — отдельная страница с фото и описанием проектов. | Реализовано для Desktop Light; требуется adaptive/theme-расширение. |
| Production landing и case-study | Hero: автопереход 5 с, после ручного действия — пауза и возобновление лишь через 10 с бездействия; нужны favicon, плавная навигация к секциям, все блоки landing, действие «Назад» на страницах кейса и Footer, совпадающий с Figma в обеих темах. | Внесено в change `refine-landing-interactions-and-visual-parity`; ожидает approval. |
| Contact form | Поле «О проекте» необязательное; обязательны «Имя», «Телефон или почта» и «Тип проекта», что отмечается `*`. У полей остаётся только нижняя граница и отделённая от поля метка. | Реализовано и проверено на клиенте, API и OpenAPI-контракте. |
| Навигация проектов | В кейсе действие «Назад» должно возвращать в историю браузера, а не принудительно в каталог; каталог также должен содержать видимую кнопку возврата. | Реализовано; при прямом открытии URL предусмотрен безопасный fallback. |
| Карусель проектов | Текущий кадр должен открываться в полноэкранном просмотре, а перетаскивание мышью — переключать фотографии. | Реализовано с закрытием по кнопке/Escape и pointer swipe. |
| Адаптивная навигация | На компактных viewport должен быть доступен раскрываемый список разделов; хедер не прокручивается вместе с контентом. | Реализовано: fixed header, mobile menu, компенсирующий верхний отступ контента. |
| Адаптивная навигация | В хедере кнопка меню располагается перед переключателем темы, чтобы тема оставалась крайним правым действием. | Реализовано. |
| Раздел проектов на landing | Для перехода из секции «Последние проекты» в полный каталог требуется явное действие справа от заголовка. | Реализовано: кнопка «Перейти» ведёт на `/projects`. |
| Тёмная тема, Profile и Contact CTA | Знак автора и CTA сохраняют тёмную поверхность и светлую типографику в обеих темах; знак соответствует Figma по внутреннему размеру и отступам. | Реализовано по контексту Figma nodes `46:11` и `46:12`. |
| Header | У имени нужен тот же знак «ПС», что и favicon. В desktop-навигации подчёркивается только активный раздел, а не все ссылки. | Реализовано: `/icon.svg` рядом с брендом, active state через hash и `aria-current`. |
| Уведомления и релизы | Оператор должен подписываться на Telegram-уведомления по заданным login/password; chat ID хранится в БД. Bot token и весь runtime env приходят из GitHub secrets, а deploy запускается только release-тегом из `main`. | Оформлено в change `add-telegram-operator-subscriptions`; ожидает approval. |
| Telegram bot | Login/password в диалоге бота — единая системная пара главного администратора, хранимая только в secrets, а не самостоятельные учётные записи подписчиков. | Зафиксировано в OpenSpec; env names будут приведены к `TELEGRAM_ADMIN_USERNAME` и `TELEGRAM_ADMIN_PASSWORD`. |
